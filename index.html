▌ GRASP / A CODE REVIEW TOOL FOR THE AGENT ERA

Don't outsource your understanding.

A LOCAL BOARD FOR THE CHANGE IN FRONT OF YOU

Claude writes most of the code now, and nobody understands what happened. Grasp puts a change on a board you can actually read. Nothing is posted, pushed or merged until you click for it.

01 WHAT IT IS

A Claude Code plugin with two jobs.

One board, whether the change is yours or someone else's: what it does, a diagram, where it can break, what it reuses, screenshots when it touches a screen, and findings you accept or drop one by one. The diff is on it, but it is the least prominent thing there.

▌ JOB 01

Understand your own change while you build it.

Takes a ticket or a sentence, writes the change, runs the real tests, and puts the result on the board. A draft pull request opens only when you click for one.

> /grasp:ship SOME-123
▌ JOB 02

Understand someone else's before you approve it.

The same board for a pull request. Your review reaches GitHub comment by comment, each one approved by you.

> /grasp:review 1234
grasp — board ● nothing leaves without a click

claude ~ %

The board is the product.

Open it once. It lists the changes waiting on your review, smallest first. Click one and the session picks it up; each section lands on the board as it is written. You will not need the terminal again.

  • Board binds to loopback, your files stay on your disk
  • Session reads, greps and runs commands, never writes to your repo
  • You accept or drop each finding, then click to post
02 WHAT IS ON A BOARD
Written from the diff, before any reviewer returns.

A finding carries its evidence or it is dropped. Findings are ranked and collapsed, never hidden, and every demotion says why. Zero findings on a clean change is the correct answer.

01What it does
The change in plain words, from the diff, not the description.
02A diagram
The code it touches, drawn. Select a few lines and ask to be shown them.
03A note per file
Why each file is in the change, and which ones are not what the change claims.
04Where it can break
Hazards that pass tests and fail in production, named for this repository.
05What already existed
Code the change reuses, and code it reinvents.
06The tests that ran
The real ones, and their result.
07Screens
Stills, a before/after pair against the base branch, or a video of a flow, whenever a change touches rendered UI.
08Findings
Each with a cited file:line, a smaller diff, a named execution path, or a rendered image.
09Your notes
Ask about a few lines or write a note. Both persist with the board, and answers arrive without you watching.
03 THE RULES IT HOLDS ITSELF TO

Nothing leaves the machine without a human click.

Verify it on your first run. Draft a review, and watch that nothing reaches GitHub until you press the button on the board.

RULE 01
No auto-posted comments, no auto-pushed commits, ever. Every comment and every push is one click, by you.
RULE 02
A review never writes to your repository. It reads, greps and runs commands.
RULE 03
The board binds to loopback and your files stay on your disk. Diagrams render offline. No request but the web font leaves the board.
RULE 04
It does not manufacture a case for rejection to look useful. Zero findings on a clean change is the correct answer.
04 MAKE IT SHARPER

Works with no configuration. Gets sharper with three layers.

Three lenses, correctness, subtraction and operability, run on every change in every repository. Everything else is optional, lives exactly once, at the layer where it is true. Later layers override earlier ones.

▌ PLUGIN

silverback-ventures/grasp

The board, the lenses, the evidence rubric, the commands. Review steps are plugins too: read the summary aloud, quiz you on the change, draw the code it touches.

→ contribute upstream

▌ PROJECT

<repo>/.grasp/ · checked in

How the lenses adjust here, hazards that pass tests and fail in production, how to run the tests, how this repo renders, extra review steps.

> /grasp:setup · under two minutes, from the repo's own history

▌ ME

~/.grasp/me/ · never shared

Your language and tone, your hard rules, your board labels, your own review steps.

> /grasp:me · from your own GitHub activity
05 INSTALL

That is the whole install.

The board ships built, so there is no npm install and no build step. Then, in any repository, open the board and work from it.

>/plugin marketplace add silverback-ventures/grasp
>/plugin install grasp
>/grasp
